# Version 1 Data Contracts

## Portable Input and Trusted Preparation

input.json contains documents: [{id,title,markdown,file_type,original_name?,original_sha256?,originalFile?,author?,date?,version?,relatedVersions?}], sourceReport: {documentId,id?,criteria?,created_at?,kind?}, optional type: {criteria}, qualityOptions and optional report_language. IDs are stable ASCII letters/digits/underscore/hyphen. Unknown metadata stays null; do not infer authorship or source date from filesystem timestamps. Text originals are available as sources/ID.md; originalFile, if present, identifies a separately retained original. A Markdown extraction hash does not identify the binary original.

qualityOptions: depth deep (default) or triage; researchMode closed (default), historical or external; referenceDate YYYY-MM-DD (required in historical); externalAuthorized true (required for external); optional scope and purpose. An external authorization covers public research without disclosure of confidential data, never arbitrary active actions. The application adapter may constrain available modes. The agent records unresolved audience/deadline/decision dates in mandate assumptions rather than silently guessing.

scripts/prepare.mjs generates quality-input/manifest.json (source roles, versions, SHA-256 hashes, original metadata and duplicate origins), segments.jsonl (stable segment IDs, exact text/line/section/page/paragraph locators and separate pending states), and options.json. These are trusted inputs, not agent outputs. Existing records remain across repair passes; do not automatically regenerate a completed assessment when source hashes change. Invalidate all checks/findings depending on a changed source and their descendants. Keep new and old evidence versioned; source fingerprints and dependency IDs permit incremental resumption without duplicate IDs. This adapter starts new checks from fresh snapshots rather than automatically reusing earlier findings.

## Output Files

All records below are required in quality/. Empty JSONL files are valid for no applicable candidates/results, but absence of a file is not empty coverage. Each JSONL row is one object. IDs must be unique across all registers, and every typed reference must resolve in its correct register. References to findings may not create a circular dependency. Preserve quotes separately from paraphrases.

A locator is {documentId,startLine,endLine,quote,sourceHash,physicalPage,printedPage,section,paragraphId}. documentId must resolve to a manifest source or authorized retained external source; sourceHash is the exact SHA-256 of that source's text, quote is a nonempty exact substring of the inclusive source lines. Page/section fields and paragraphId may be null when unknown; line locators and hashes remain mandatory. Record binary/render limitations separately. Evidence used to confirm material findings must identify how the original was checked or explicitly limit the finding to the available extracted text.

mandate.json: {id,targetDocumentId,targetVersion,scope,purpose,audience,reportDate,coveredPeriod,decisionDate,evaluationDate,referenceDate,temporalBasis,researchMode,depth,profiles:[{id,reason}],materiality,criteriaIds,assumptions,limits}. Scope/purpose/materiality/temporalBasis are nonempty text; unknown descriptive/date metadata is null. Profiles are scientific, ai, progress, decision, commercial, technical, security, audit, incident, review; use one or more with reasons. Match configured depth/mode/cutoff. targetVersion must match the trusted manifest. Do not automatically widen scope or ignore the supplied purpose.

claims.jsonl: {id,text,locator,type,qualifications,importance,premiseIds,status,limitations}. Text is faithful; type identifies fact/result/quantity/comparison/causal/obligation/prediction/recommendation/implicit; qualifications is an object preserving population, period, conditions, modality and quantifiers. importance is contextual text. premiseIds reference other claims. status: supported_within_limits, contradicted, insufficient_support, ambiguous, unverifiable, out_of_scope. limitations is an array. Claims are not findings.

criteria.jsonl: {id,text,basis,scope,validFrom,validTo,obligation,exceptions,applicability,claimIds,evidenceIds,coverage,reason}. basis is {kind:"source",locator}, {kind:"derived",locators,interpretation}, or {kind:"mandate",field,quote}. Mandate fields may only reference supplied type.criteria, sourceReport.criteria, qualityOptions.scope or qualityOptions.purpose, with an exact quote. An analyst-proposed expectation needs derived basis and cannot masquerade as law. obligation: mandatory/advisory/interpretation. applicability: applicable/not_applicable/unknown. coverage: addressed/justified_absence/unverifiable/not_applicable/pending. Explain applicability and unknowns. Include configured Q01–Q08 methodology criteria as well as substantive applicable dossier requirements. References to evidence/claims are explicit, not a count alone.

evidence.jsonl: {id,claimId,relation,locator,originId}. relation: supports/contradicts/qualifies/depends_on/supersedes/same_origin; originId identifies the underlying informational origin. Count duplicate origins once. An evidence row always points to a claim; a finding may also use direct source locator through its object.

checks.jsonl: {id,kind,status,claimIds,criterionIds,findingIds,locators,method,result,artifactPaths,limitation}. kind: comparison/numeric/omission/counterevidence/alternative/profile/original_review/serious_revisit/independent_review. status: executed/unavailable/not_applicable/pending/failed. method/result are nonempty inspectable text; execution/result are not private internal reasoning. Unavailable/failed/pending need a nonempty limitation. Referenced artifacts are retained relative paths under quality/, with original source versions linked through locators. Numeric checks require preserved calculation input/output and explicit formula/unit/tolerance/rounding/missing-data rules in method/result. original_review records identify what binary/render/text original was inspected, not just its extracted paragraph.

omissions.jsonl: {id,expected,basisCriterionIds,searchedSegmentIds,synonyms,coverage,materiality,verdict,checkIds,findingId}. verdict: found/confirmed_absent/clarification/unverifiable/rejected; coverage is bounded text. A confirmed_absent row needs searched segments, applicable basis, consequence, an executed omission check and its confirmed finding. Found/rejected entries remain to suppress false positives.

findings.jsonl: {id,title,categories,profiles,level,object,criterionIds,evidenceIds,checkIds,challenge,verdict,impact,severity,severityReason,urgency,urgencyReason,confidence,confidenceReason,remedy,closure,dependentClaimIds,relatedFindingIds,limitations,originalReview}. object is {text,locator}; omitted material uses the relevant requirement/report-scope anchor, never a fictional quotation. categories are F01–F12. level: target/original/reviewer. verdict: confirmed/narrowed/clarification/rejected/out_of_scope. challenge is {alternative,checkIds,result}; result must describe what defeated or preserved the candidate. Confirmed/narrowed need all fields, nonempty applicable criteria, actual evidence and executed checks, contextual impact, remedy and closure. severity: critical/major/moderate/minor; urgency: immediate/before_decision/scheduled; confidence: high/medium/low. Low confidence cannot be a confirmed allegation. originalReview is {status:"verified"|"limited",checkIds,limitation}; limited needs a reason and narrows what is alleged. Major/critical confirmations require an executed serious_revisit that names this finding and original-review evidence. Link root causes, avoid duplicate manifestations; relatedFindingIds reference findings.

review-coverage.jsonl: {id,originalClaimId,reviewerClaimId,findingId,status,reason,checkIds}. Required, may be empty except when review profile is active. originalClaimId may be null only for an unverifiable entry when originals are inaccessible; do not fabricate a claim or locator for a missing document. status: covered_correctly/covered_partially/omitted/unjustified_criticism/unverifiable. Before calling an issue omitted, demonstrate that it was in the previous reviewer's scope and then-available material. Include an independent_review check over available original-source segments; compare against the reviewer's list only after that pass. Preserve original vs reviewer levels.

external-sources.jsonl: {id,url,accessedAt,publishedAt,version,content,sha256,availability,role}. Required but empty in closed mode. Only external-authorized mode permits external entries; public http(s) URLs, access date, version and exact content hash are mandatory. An inaccessible source is a limitation, not invented content. External evidence is cited with its retained locator in registers and a dated URL in prose alongside the target passage, which proves what the report says, not the external fact. Never transmit confidential dossier fragments to obtain external evidence. Historical mode in this adapter uses only supplied sources and the declared cutoff.

coverage.json: {id,completion,segments,sources,gates,plannedCheckIds,verifiedClaimIds,limitations,counts}. completion: complete/incomplete/triage. segments enumerates every prepared segment exactly once with id, sourceHash, extraction (extracted/unavailable), reading (read/unavailable/pending), claims (checked/not_applicable/unverifiable/pending), requirements (checked/not_applicable/unverifiable/pending), reason. sources enumerates every manifest source with id, originalReview verified/limited/unavailable and reason; record missing sources/annexes separately in limitations. gates enumerates G1–G7 with id,status passed/limited/failed and reason. counts has segmentsRead,claimsChecked,confirmedFindings computed from these registers. plannedCheckIds must enumerate every recorded check; verifiedClaimIds is exactly claims with statuses supported_within_limits/contradicted/insufficient_support/ambiguous. Complete needs deep mode, all segments resolved, all applicable criteria resolved, all checks resolved, no failed gates and explicit limitations for unavailable checks/material. Unverifiability is an outcome, not positive conformity. Triage cannot be complete. Incomplete records may be published with explicit missing work; invalid/untraceable findings cannot.

report.md includes `<!-- quality-summary: COMPLETE_STATE; confirmed=N -->` where state matches coverage (complete/incomplete/triage), each confirmed ID exactly once as `<!-- finding: ID -->` and once as `<!-- finding-detail: ID -->`. Do not put rejected candidates in these confirmed lists. Stable markers remain English; prose follows Report Language. Follow the report template; Deep Proof additionally requires evidence footnotes and criterion markers. The standalone validator verifies registers and summary markers; Deep Proof separately validates chapter/citation rules.

## Tools and Limits

`node scripts/validate.mjs WORKSPACE` validates identity, references, exact quotes/hashes, coverage, gate consistency, confirmed finding fields, challenge and serious-review records, arithmetic artifacts and narrative count markers. It rejects linked/outside/oversized artifacts. `scripts/check_numbers.py` provides declared Decimal arithmetic only. Neither tool verifies semantic relevance, truthful descriptions of performed visual checks, domain appropriateness, causal impact or completeness of extracted material. Never label these gates as certification. Acceptance evaluation and answer keys live outside this skill and are not copied to jobs.
