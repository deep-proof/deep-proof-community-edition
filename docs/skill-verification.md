# Analyst Skill Verification Standard

An Analyst Skill is a decision procedure. It tells an AI agent which evidence matters, how to weigh it, which thresholds trigger a concern and how to present the result. A report produced with it will be read by people who make investment, credit, procurement, compliance or legal decisions. The skill must therefore be treated like any other instrument that influences such decisions: it is trusted only after it has been measured.

Deep Proof applies one simple rule. **Every Analyst Skill is Use With Caution until an accountable person has evaluated it scientifically and attached a verification certificate.** Every report produced with a Use With Caution skill carries the USE WITH CAUTION label from the moment the analysis starts, in the application and in every exported PDF page.

> A fluent, well-cited report is not evidence that the method behind it is correct. Verification is the evidence.

## Use With Caution And Verified

| Status | How a skill gets it | What the platform does |
| --- | --- | --- |
| **Use With Caution** | Default for every skill: generated by Deep Proof, imported packages without a certificate, and any skill whose rules were edited or regenerated after verification. | The skill shows a Use With Caution badge. Every analysis started with it is labelled USE WITH CAUTION in the reader, in the analysis history, in the PDF header, on every PDF page and in the PDF filename. |
| **Verified** | Imported with a valid `verification-certificate.md` at the root of the skill package, and unchanged since. | The skill shows a Verified badge. Reports show who verified the skill, when, and on how many evaluation cases. |

The label is recorded in the analysis snapshot when the run is created. It cannot be removed later: verifying a skill tomorrow does not turn yesterday's Use With Caution reports into verified ones, because they were produced by an unmeasured method.

Skills generated inside Deep Proof are always Use With Caution. An AI system cannot certify its own work: the generator would be grading the generator. If a generated package contains a certificate file, the platform discards it.

## Requirements For Skill Creators

These requirements apply to every creator of verification skills, whether a human analyst, a consultant, or an AI skill creator such as the built-in `review-design` skill. A skill package is complete only when it satisfies the [import contract](/api/admin/skill-import-contract) and the following verification-oriented requirements.

- **Defined decision scope.** State the decision the skill supports, the dossier types it accepts, and what it explicitly does not assess. A skill without a boundary cannot be tested, because there is no definition of a correct answer.
- **Explicit, testable criteria.** Each criterion in `references/review-criteria.md` has a stable ID and an observable test: what evidence is required, what result means pass, concern or fail, and what counts as missing evidence. Vague criteria such as "assess governance quality" are not measurable.
- **Traceable thresholds.** Every numeric threshold or decision rule cites its source in `references/source-map.md`. Thresholds invented by the creator, or example figures promoted into rules, are prohibited.
- **Uncertainty and abstention.** The methodology states when the agent must report "not assessable" instead of guessing. A skill that always produces a confident answer is unsafe by design.
- **Deterministic helpers where possible.** Calculations, reconciliations and coverage checks belong in tested helper scripts under `scripts/`, with documented inputs, outputs and known limits, rather than in free-form model reasoning.
- **An evaluation plan delivered with the skill.** Creators should ship `evals/evaluation-plan.md` describing the intended test population, the critical failure modes, the metrics and the proposed acceptance thresholds. Test cases and expected outcomes may be stored under `evals/` as Markdown, JSON or CSV files.
- **No self-certification.** A creator, human or AI, never writes `verification-certificate.md` for a skill it has just produced. Certification is a separate step performed by an accountable reviewer after the evaluation is complete.

## Why Every Skill Must Be Scientifically Evaluated

Large language model agents are persuasive. They write clear prose, produce tables and charts, and attach citations to exact quotations. Deep Proof validates that each citation exists, that line numbers are valid and that quotes match the source. That check proves that the evidence was **quoted correctly**. It does not prove that the evidence was **interpreted correctly**, that the most important evidence was found, or that the conclusion follows. Only a structured evaluation against known answers can measure those properties.

### What can go wrong without evaluation

- **Missed red flags.** The most expensive failure is a false negative: a revenue concentration, an undisclosed liability, a sanctions exposure or a covenant breach that the skill does not detect. The report looks complete, so nobody looks again.
- **False alarms.** An over-sensitive skill flags healthy counterparties as high risk. Good suppliers are rejected, sound credit applications are declined, and valuable clients are told they failed a review they should have passed.
- **Plausible but wrong reasoning.** The agent may cite a real sentence while drawing the wrong conclusion from it: a quoted figure from the wrong period, a draft instead of a signed contract, a management assertion treated as independent proof.
- **Inconsistency between runs.** Model outputs vary. The same dossier can receive different ratings on different days. Without repeated runs during evaluation, nobody knows how large that variation is or whether it changes a decision.
- **Silent drift.** A model upgrade, a new agent version or an edited playbook can change behaviour substantially. A skill that was acceptable last quarter may not be acceptable today.
- **Hidden bias.** A method can systematically disadvantage smaller companies, particular jurisdictions, document formats or languages. Bias is invisible in a single report and only appears when results are compared across a representative test set.
- **Automation bias.** Reviewers trust polished output and reduce their own scrutiny. An unverified skill therefore does more harm than no tool at all: it replaces careful human review with confident, untested automation.

### The cost to your organization

- **Loss of clients.** Clients buy judgment. One report that wrongly clears a failing target or wrongly rejects a sound one can end a relationship built over years, and trust lost through a visible error is rarely recovered.
- **Financial damage.** Decisions based on a flawed analysis lead to bad investments, credit losses, overpayment in transactions, failed suppliers and the cost of unwinding them.
- **Legal liability.** Advisers, auditors and analysts owe a professional duty of care. Delivering an analysis produced by an untested method can be negligence, and contractual warranties about diligence quality may be breached.
- **Regulatory exposure.** Many sectors require documented, validated and monitored models and controls, for example model risk management in financial services, AI governance obligations and data protection rules. An unevaluated automated assessment is difficult to defend to a regulator or an auditor.
- **Reputational harm.** Errors made by AI attract attention. A single public failure can damage the brand of the firm that signed the report, not only the tool that drafted it.
- **Operational cost.** Rework, internal investigations, client remediation and insurance claims usually cost far more than a proper evaluation would have cost before deployment.

An evaluation does not make a skill perfect. It makes its error rates **known**, so that the organization can decide responsibly where the skill may be used, where a human must always review, and where it must not be used at all.

## How To Evaluate An Analyst Skill

A verification is an experiment with a written protocol, decided before the results are seen. The following elements are required for a certificate to be credible.

### 1. Evaluation dataset

- Build a set of dossiers that represents real use: typical cases, borderline cases, clean cases and cases containing known problems. Include the document formats, sizes and languages the skill will actually receive.
- Include adversarial cases: contradictory documents, missing documents, misleading management statements, figures from mixed periods and irrelevant material.
- Keep a held-out portion that the skill creator never saw while writing or tuning the skill. Tuning on the test set produces optimistic results that will not hold in production.
- Use synthetic or properly authorised data. Never place confidential client data in an evaluation set without permission.
- The number of cases must be large enough for the decision at stake. A few demonstrations are not an evaluation; aim for dozens of cases per critical criterion and report the resulting confidence intervals.

### 2. Reference answers

- Independent domain experts assess every case without seeing the skill's output, criterion by criterion, including which findings are critical.
- Where judgment is involved, use at least two independent reviewers and measure their agreement, for example with Cohen's kappa. If experts disagree, the criterion is not yet defined precisely enough to be automated.
- Record the expected status, the key evidence and the findings that must not be missed.

### 3. Method

- Freeze the skill revision, the agent and the model before testing, and record their identifiers.
- Run every case several times, at least three, to measure run-to-run variation.
- Compare outputs with the reference answers blind to which run produced them, using a written scoring guide.
- Pre-register the acceptance thresholds: for example, no missed critical finding, recall on material findings of at least 95 percent, and a false-alarm rate below an agreed limit.

### 4. Metrics

| Metric | What it measures | Why it matters |
| --- | --- | --- |
| Recall on critical findings | Share of known critical problems the skill reports | Missed problems cause the largest losses |
| Precision | Share of reported concerns that are real | False alarms damage clients and trust |
| Criterion agreement | Agreement between skill status and expert status for each criterion | Shows which criteria are reliable |
| Citation support rate | Share of cited assertions that experts confirm are actually supported by the quote | Detects plausible but wrong reasoning |
| Abstention quality | Whether the skill reports "not assessable" when evidence is genuinely missing | Prevents confident guesses |
| Run-to-run stability | Variation of statuses and conclusions across repeated runs | Measures consistency and fairness |
| Subgroup performance | Metrics split by document type, sector, size, language or jurisdiction | Reveals hidden bias |

### 5. Results and limitations

- Report every metric with its sample size and confidence interval, including failures. Do not remove inconvenient cases.
- Describe the conditions in which the skill must not be used, and the review steps a human must always perform.
- Decide the scope of approval: full use, use with mandatory human review, or rejection.

### 6. Maintenance

Verification applies to one exact methodology. Repeat the evaluation, at least on a regression subset, after any change to criteria, playbook, report template or reference material, after a change of agent or model, and periodically during production use.

## The Verification Certificate

A skill becomes Verified when its package contains a file named `verification-certificate.md` at the root, next to `SKILL.md`. Deep Proof checks the certificate's structure when the skill is imported and rejects malformed certificates. The platform verifies that the certificate is present and complete; it cannot verify that its statements are true. The certificate is a signed professional attestation, and responsibility for its content rests with the person and organization named in it.

Required frontmatter fields:

| Field | Content |
| --- | --- |
| `verified_by` | Name, role and organization of the accountable reviewer |
| `verified_on` | Date of approval in `YYYY-MM-DD` format |
| `evaluation_cases` | Number of evaluation dossiers, as a positive whole number |
| `model` | Optional. Agent and model used during the evaluation |

Required sections: **Scope**, **Evaluation Dataset**, **Method**, **Results** and **Limitations**. A **Sign-Off** section is recommended.

```markdown
---
verified_by: Jane Doe, Head of Credit Risk, Example Capital
verified_on: 2026-09-30
evaluation_cases: 120
model: codex / gpt-6-luna
---

# Verification Certificate — Supplier Risk Review

## Scope
Mid-market supplier dossiers in English and Romanian; contracts, delivery records,
financial statements. Out of scope: sanctions screening, sovereign counterparties.

## Evaluation Dataset
120 dossiers (80 development, 40 held out), 31 with known critical findings,
18 adversarial cases. Reference answers by two independent analysts, kappa 0.82.

## Method
Skill revision frozen; three runs per dossier; blind scoring against a written guide;
acceptance thresholds pre-registered on 2026-09-01.

## Results
Critical-finding recall 100% (31/31); material-finding recall 96% (95% CI 91–98%);
precision 89%; status stability across runs 97%. No significant subgroup gap.

## Limitations
Scanned documents without OCR are not supported. Human review remains mandatory
for exposures above EUR 5 million.

## Sign-Off
Approved for production use with the human-review condition stated above.
```

## What Removes Verification

| Change | Result |
| --- | --- |
| Editing Review Criteria, Review Playbook or Report Template | New revision without the certificate: Use With Caution |
| Regenerating the methodology or changing reference files | Regeneration needed, then a generated revision: Use With Caution |
| Renaming the skill | Verification is kept, because the methodology is unchanged |
| Changing the agent or model in configuration | Not detected automatically. Re-evaluate before relying on the certificate |

To restore Verified status, evaluate the changed skill and import it again with an updated certificate.

## Checklist Before Using A Skill For Real Decisions

- The skill scope matches the decision and the dossier.
- The skill shows the Verified badge, and the certificate is recent and names an accountable reviewer.
- The certificate covers the agent and model currently configured.
- The limitations in the certificate are respected, including mandatory human review.
- Reports labelled USE WITH CAUTION are never delivered to clients or used as the basis of a decision.
